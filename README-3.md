# Transaction Fraud Detection & AI Investigation Assistant

An end-to-end fraud detection system: gradient-boosted fraud scoring, an
unsupervised anomaly backstop, a three-tier decision policy, SHAP
explainability, and an LLM agent that writes analyst-ready investigation
summaries — served as a FastAPI microservice.

Built on the IEEE-CIS Fraud Detection dataset (590,540 real e-commerce
transactions, ~3.5% fraud rate).

## Architecture

```
                ┌──────────────────────────────────────────────┐
 transaction →  │  Detection Agent                             │
 (74 features)  │  • XGBoost production model → fraud probability
                │  • Isolation Forest → anomaly score (0–1)     │
                └──────────────┬───────────────────────────────┘
                               ▼
                ┌──────────────────────────────────────────────┐
                │  Decision Agent (three-tier policy)          │
                │  • score ≥ 0.90            → BLOCK           │
                │  • score ≥ 0.70            → INVESTIGATE     │
                │  • anomaly ≥ 0.80          → INVESTIGATE ◄───┼── backstop:
                │  • else                    → APPROVE         │   catches novel
                └──────────────┬───────────────────────────────┘   attacks the
                               ▼                                  supervised
                ┌──────────────────────────────────────────────┐   model misses
                │  Investigation Agent (gpt-4o-mini)           │
                │  SHAP top-5 drivers + scores → 2–3 sentence  │
                │  analyst summary. Fail-open: API still       │
                │  returns the verdict if the LLM is down.     │
                └──────────────────────────────────────────────┘
```

## Results (held-out future window, time-based split)

| Model | ROC-AUC | PR-AUC | Notes |
|---|---|---|---|
| XGBoost (base, 74 features) — **shipped** | 0.904 | 0.722 | Selected by A/B test |
| XGBoost + anomaly feature (hybrid) | 0.903 | 0.720 | ΔPR-AUC −0.002 (within noise) |
| Isolation Forest (unsupervised) | 0.835 | 0.301 | 3.5× lift in top 5% — used as decision backstop |

The hybrid added nothing measurable, so the simpler base model ships; the
anomaly score still earns its place as an independent backstop tier
(see `models/hybrid_metrics.json` for the A/B record).

### Operating thresholds (tuned on validation, evaluated on untouched future data)

| Threshold | Precision | Recall | Role |
|---|---|---|---|
| 0.90 | 1.00 | 0.08 | BLOCK |
| 0.70 | 1.00 | 0.20 | INVESTIGATE |

The policy is deliberately precision-first: near-zero false alarms at the
top of the queue, with the anomaly backstop catching outliers the
supervised model scores low.

## Quickstart

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# regenerate model bundles (optional if you have the .pkl files):
# run notebooks 01 → 06 in order

uvicorn api.main:app --reload
# docs: http://127.0.0.1:8000/docs
```

Optional — LLM investigation summaries (the API works without this,
falling back to a manual-review message):

```bash
echo "OPENAI_API_KEY=sk-..." > .env   # restart the server afterwards
```

## Example

```bash
curl -X POST http://127.0.0.1:8000/predict_fraud \
  -H "Content-Type: application/json" -d @sample_fraud.json
```

```json
{
  "fraud_probability": 0.0799,
  "anomaly_score": 0.9126,
  "decision": "INVESTIGATE",
  "triggered_rule": "anomaly_score >= anomaly_threshold",
  "investigation_summary": "This transaction is flagged ... high anomaly score of 0.91 ... despite a low model fraud probability of 0.08 ...",
  "explanations": [{"feature": "C5", "impact": -0.899}],
  "processing_time_ms": 3726.27
}
```

A real fraud the supervised model scored 0.08 — caught by the anomaly
backstop. That is the design working as intended.

## Key design decisions

- **Time-based split only** (70/10/20 train/val/future). Random splits leak
  customer velocity features and inflate metrics.
- **Train-window preprocessing travels in the model bundles** (scaler,
  log1p columns, normalization stats), so serving transforms are
  bit-identical to training — verified by local-vs-API score parity.
- **Thresholds ship inside the model bundle**, so the API always applies
  the exact policy that was evaluated.
- **Fail-open LLM layer**: no key, network, or quota → the API still
  returns scores, decision, and SHAP evidence.
- **Privacy**: only model evidence (scores, SHAP values) is sent to the
  LLM — never raw card or customer identifiers.

## Limitations & future work

- Precision-first policy trades recall: ~80% of frauds score below the
  investigate threshold. Lower thresholds raise recall at real
  false-positive cost (see notebook 06's threshold table).
- Velocity features must be precomputed per customer history; a
  production deployment needs a streaming feature store.
- IEEE-CIS is 2019 data; drift monitoring and scheduled retraining would
  be the next production steps.
